# scripts/

เครื่องมือเล็ก ๆ ที่ใช้ตรวจหน้าโจทย์ใน `/cp/` เขียนไว้เพราะแต่ละตัวเคยถูกเขียนใหม่จากศูนย์
ในเซสชันที่ต่างกัน และแต่ละตัวมีกับดักที่กินเวลาไปแล้วจริง ๆ ตอนเขียนครั้งแรก

รันด้วย `node` ไม่ต้องลงอะไรเพิ่ม

## `extract-cp-code.mjs`

ดึงโค้ดที่หน้า `/cp/<slug>/` ship จริงออกมาจาก `dist` เพื่อเอาไปคอมไพล์ซ้ำ

```bash
npm run build
node scripts/extract-cp-code.mjs tears /tmp/out
```

หน้าโจทย์ทุกหน้าเขียนโดยวางไฟล์ `.cpp` ที่เทสต์แล้วลงในเทมเพลตสตริง ซึ่งเป็นขั้นที่โค้ดเพี้ยนได้เงียบ ๆ
เคยเกิดมาแล้วทั้งบรรทัดหายและตัวแปรถูกลบทิ้ง สิ่งที่ต้องคอมไพล์ซ้ำจึงเป็นโค้ดในหน้า ไม่ใช่ไฟล์ที่เทสต์
เสร็จแล้ว `diff` กับไฟล์ต้นทาง ควรต่างกันไม่เกินบรรทัดว่างท้ายไฟล์

กับดักที่สคริปต์นี้แก้ไว้ให้แล้ว: shiki เขียน `<` เป็น entity แบบตัวเลข `&#x3C;` ถ้าถอดแค่ `&lt;`
ไฟล์ที่ได้จะเต็มไปด้วย `N &#x3C;= 1e5` แล้วคอมไพล์พังโดยที่ error ไม่ได้บอกสาเหตุจริง

## `check-io-spaces.mjs`

ตรวจว่าตาราง EXAMPLE ของหน้าไหนกำลังทำช่องว่างหาย

```bash
node scripts/check-io-spaces.mjs          # ตรวจจาก source ใช้กันของใหม่หลุด
node scripts/check-io-spaces.mjs --dist   # ตรวจจาก dist ว่าเรนเดอร์ออกมาจริงเป็นยังไง
```

JSX กลืนช่องว่างที่เขียนคั่นระหว่างสอง `{expr}` ภายใน fragment `<>...</>` ทำให้ `4 9 3 6` กลายเป็น `4936`
และ `1999999 2000000` กลายเป็น `19999992000000` ซึ่งอ่านผิดความหมายไปเลย โดยที่ `check`, `lint`
และ `build` เขียวทั้งหมด เคยหลุดไป 22 ไฟล์ก่อนมีคนสังเกตเห็น

พังเฉพาะใน fragment ส่วนที่เขียนตรง ๆ ใน `<td>` เช่น `{N} {M}` เรนเดอร์ถูกอยู่แล้ว
**อย่าไล่แก้ทุกที่ที่ grep เจอ `} {`** เพราะเคยนับได้ 115 จุดใน 40 ไฟล์ ทั้งที่พังจริง 36 จุดใน 22 ไฟล์
แก้โดยรวมทั้งบรรทัดเป็นสตริงเดียว `{[a, b, c].join(' ')}`

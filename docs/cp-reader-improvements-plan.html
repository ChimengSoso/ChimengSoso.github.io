แผนงานชั่วคราว: สามเรื่องที่ทำให้ /cp/ อ่านง่ายขึ้น

สร้างเมื่อ 2026-09-09 · ข้อ 1 และ 2 ปิดแล้ว เหลือข้อ 3 ที่รอเจ้าของตัดสิน

ไฟล์นี้เป็นของชั่วคราว ลบทิ้งเมื่องานเสร็จครบทั้งสามข้อ

ทรงเดียวกับ docs/cp-derivation-narrative-plan.md และ docs/cp-knowledge-uplift-plan.html ที่ถูกลบไปแล้วหลังงานลง ตอนปิดงานให้ย้ายบทสรุปไปไว้ใน docs/ROADMAP.md ข้อ 11 แล้วลบไฟล์นี้

ที่มาของงานนี้

เจ้าของถามในเซสชันวันที่ 2026-09-09 ว่า ถ้าเป็นคนอ่านบทความ /cp/ เอง มีอะไรอยากปรับปรุงเพิ่มไหม โดยยึดหลักสี่ข้อคือ อ่านง่ายเข้าใจง่าย, มีสะพานเชื่อม, มีตัวอย่างที่ถูก และ มีตัวอย่างที่ผิด

ผลการตรวจคือสามในสี่ข้อแข็งอยู่แล้ว ส่วนที่ขาดชัดที่สุดคือ ตัวอย่างที่ผิด รองลงมาคือ สะพานเชื่อม ที่ถูกพูดถึงในเนื้อความแต่ไม่ได้ทำเป็นลิงก์

ข้อจำกัดที่ต้องรู้ก่อนใช้ไฟล์นี้

ตัวเลขทั้งหมดข้างล่างมาจากการวิเคราะห์ โครงสร้าง ของไฟล์ (นับหัวข้อ ลิงก์ โค้ดบล็อก ความยาว) ไม่ได้มาจากการนั่งอ่านเนื้อความทั้ง 29 หน้าจนจบแบบคนอ่านจริง เรื่องที่ต้องอ่านจริงถึงตัดสินได้ เช่นจังหวะการอธิบายรายย่อหน้า หรือคำที่กลอสแล้วยังงง ยังไม่ได้ตรวจ ถ้าจะทำข้อ 1 หรือ 3 ให้อ่านหน้านั้นเต็ม ๆ ก่อนเสมอ

การแบ่งงานแบบขนาน

ทุกหน้าเป็นไฟล์ของตัวเองและไม่มีโค้ดร่วมกัน งานจึงแตกขนานได้ตามไฟล์ ตารางนี้คือสัญญาว่าใครแตะไฟล์ไหน agent อ่านแถวของตัวเองแถวเดียวก็ทำงานได้ ไม่ต้องคุยกับใคร

บทเรียนเรื่องวิธีนับ ที่ทำให้ประเมินงานผิดสามรอบติด

การนับ "จำนวนครั้งที่หน้าหนึ่งเอ่ยถึงบทหนึ่ง" ด้วย grep ทั้งไฟล์ ใช้ตัดสินใจไม่ได้ เพราะไฟล์ .astro มีทั้ง frontmatter, คอมเมนต์, สตริงโค้ด C++ และป้ายใน SVG ปนอยู่ ตัวเลขที่เคยประเมินไว้ (13 ลิงก์ แล้วเหลือ 5 แล้วเหลือ 4) สุดท้ายของจริงคือ 2

กฎของ agent ที่ทำงานขนาน ห้ามข้าม

  1. แตะเฉพาะไฟล์ในแถวของตัวเอง ไฟล์อื่นห้ามแก้เด็ดขาด แม้จะเห็นว่ามันผิด ให้รายงานกลับแทน
  2. ห้ามรัน npm run build / check / lint ทั้งสามเขียนลง dist/ และ .astro/ ที่เดียวกัน รันพร้อมกันแล้วพัง ผู้ประสานงานรันครั้งเดียวตอนจบ
  3. ห้ามรันคำสั่ง git ที่เขียน (add, commit, checkout, stash) เพราะ index เป็นของร่วม ผู้ประสานงาน commit เอง
  4. ห้ามแก้ docs/ หรือ CLAUDE.md ถ้าเจอ convention ใหม่ ให้เขียนไว้ในข้อความสรุปตอนจบ ผู้ประสานงานจะเป็นคนจด
  5. ห้ามอ้างว่าโค้ดผ่านถ้ายังไม่ได้รันจริง ถ้าคอมไพล์ไม่ผ่านหรือผลไม่ตรงกับที่หน้านั้นเล่าไว้ ให้รายงานตรง ๆ ว่าไม่ตรง อย่าดัดโค้ดให้เข้ากับเรื่อง และอย่าดัดเรื่องให้เข้ากับโค้ดโดยพลการ

คอมไพล์ C++ ที่เครื่องนี้

Windows ไม่มี g++ ติดตั้งไว้ (ตรวจแล้วทั้ง g++, gcc, cl, clang++ และใน C:\msys64 ก็ไม่มี) แต่ WSL Ubuntu มี g++ 11.4.0 ใช้ผ่านสูตรนี้ 

wsl -e bash -lc 'mkdir -p ~/cpwork && cd ~/cpwork &&
  cp /mnt/c/Users/chi.cm/AppData/Local/Temp/<ไฟล์>.cpp . &&
  g++ -O2 -o prog <ไฟล์>.cpp && echo "<อินพุต>" | ./prog'

เขียนไฟล์ .cpp ลง Windows temp ก่อน แล้วค่อยก๊อปเข้า WSL ทำงานใน ~/cpwork ของ WSL เอง เร็วกว่าทำบน /mnt/c มาก ทดสอบแล้วว่าใช้ได้จริง

ข้อ 1 · ยังไม่มีโค้ดที่ผิดให้ดูสักบรรทัด ทำก่อน

หลักฐาน

ไล่ชื่อ <CodeBlock> ทุกอันในคลังได้ 132 บล็อก และ ไม่มีสักบล็อกเดียวที่เป็นโค้ดผิด ทุกอันเป็นโค้ดที่ถูก แบ่งเป็นเฉลยเต็ม, หัวใจของทั้งข้อ, เฉลยชุดทดสอบย่อย, ท่าที่สอง และ brute*.cpp ที่เป็นตัวตรวจ (ถูกแต่ช้า)

แต่มีอย่างน้อยห้าหน้าที่ เล่าเรื่องบักเฉพาะเจาะจงซึ่งผ่านตัวอย่างในโจทย์ครบทุกชุด คนอ่านได้บทเรียนเป็นร้อยแก้ว แต่ไม่เคยเห็นบรรทัดที่ผิดวางข้างบรรทัดที่ถูก ซึ่งเป็นจุดที่ "รู้" กับ "จำได้" ต่างกันมาก

วัตถุดิบที่มีอยู่แล้ว รอแปลงเป็นโค้ด
หน้าบักที่หน้านั้นเล่าไว้อยู่ในกล่องชื่อ
islandsคำนวณ best ของต้นไม้ห้อยถูกแล้ว แต่ลืมเอาไปใช้ เหลือ (void)best; ตัวสุ่มจับได้ที่ n = 6 ตอบ 18 ของจริง 21เรื่องจริงที่เกิดขึ้นตามลำดับ
pyramid-baseใบส่วนเกินของเซกเมนต์ทรีตั้งเป็น 0 แทนอนันต์ mn[1] จึงเป็นศูนย์ตลอด เคสแรกที่จับได้คือ M=9, N=6, B=10ที่มา และสามรอบที่ยังผิด
teleportersเครื่องที่เหลือหลังไม่มีวงให้ดูด ให้ +2 ต่อเครื่อง ของจริงคือ +1 แล้ว +3เรื่องจริงที่เกิดขึ้นตามลำดับ
archeryสูตรการไหลติดลบตอนเป้า 1 ไม่มีนักธนูแข็ง และการเดาว่า u(k) ข้ามพหุคูณของ N ได้ครั้งเดียวที่มา และสามรอบที่ยังผิด
sailsกฎตัดสินตอนค่าเสมอกัน ไม่ได้ทำให้คำตอบผิดตรง ๆ แต่ทำลายความเป็นระเบียบที่โค้ดชั้นในพึ่งอยู่ผมแก้ถูกตั้งแต่แรก แต่เข้าใจเหตุผลผิดอยู่นาน

ทรงที่เสนอ

ใส่ <details class="expander"> เพิ่มหนึ่งอันในหัวข้อโค้ดของหน้านั้น ชื่อประมาณ "โค้ดที่ผิด กับบรรทัดเดียวที่ต่างกัน" โดยข้างในมีสามอย่าง

  1. snippet ที่พัง เฉพาะส่วนที่ผิด ไม่ใช่ทั้งไฟล์ พร้อมคอมเมนต์ชี้บรรทัด
  2. อินพุตที่หักมันได้ ตัวเล็กที่สุดที่ทำให้เห็นผลต่าง (สี่หน้าในตารางมีเลขนี้อยู่ในเนื้อความแล้ว)
  3. ผลที่ออกมาผิดเทียบกับที่ถูก เป็นตัวเลขสองตัววางคู่กัน

กฎที่ห้ามลืม

บล็อกนี้เป็นส่วนหนึ่งของเฉลย จึงต้องอยู่ ใน <Spoiler> ตามกฎ reveal-after-hint และโค้ดที่ผิดก็ต้อง คอมไพล์ผ่านและรันได้จริง เหมือนโค้ดอื่นในคลัง ต้องพิสูจน์ด้วยว่ามันผ่านตัวอย่างในโจทย์จริง ๆ ก่อนอ้างว่า "ผ่านตัวอย่างแต่ยังผิด" ถ้ารันแล้วไม่ผ่านตัวอย่าง แปลว่าจำเรื่องผิด ให้แก้เนื้อความ อย่าแก้โค้ดให้เข้ากับเรื่อง

  • islands · บักที่เงียบที่สุดในกลุ่มนี้ เริ่มจากหน้านี้ก่อนเพราะเล่าไว้ละเอียดสุด
  • pyramid-base · มีเคสที่จับได้ระบุไว้แล้ว (M=9, N=6, B=10)
  • teleporters · ผลต่างเป็นตัวเลขเดียว อธิบายง่ายที่สุด
  • archery · หน้ายาวสุด ทำท้ายสุด และมีบักสองตัวให้เลือกหยิบมาแค่ตัวเดียว
  • sails · ยากที่สุดที่จะแสดงเป็นโค้ด เพราะผลของบักเป็นทางอ้อม พิจารณาว่าคุ้มไหม

แก้ตัวเลขที่เคยผิดในไฟล์นี้เอง

ฉบับแรกของเอกสารนี้บอกว่ามี 6 หน้าที่ไม่มีลิงก์ออก และ 5 หน้าที่ไม่มีใครลิงก์เข้า ผิดทั้งคู่ เพราะสคริปต์ตรวจจับเฉพาะลิงก์แบบสัมพัทธ์ href="../x/" แต่คลังนี้ใช้ลิงก์ สองแบบปนกัน และอีกแบบคือแบบสัมบูรณ์ href="/cp/x/" ซึ่งหลุดการตรวจไปหมด

ตัวเลขจริงคือ ไม่มีลิงก์ออก 3 หน้า (archery, hearing-pairs, pick-books) และ ไม่มีใครลิงก์เข้า 1 หน้า (flood-walls) ส่วน rolling-state-dp, state-graph-bfs และ tree-dp ลิงก์ออกอยู่แล้วด้วยแบบสัมบูรณ์ ไม่ต้องแก้ ข้อสรุปหลักยังเหมือนเดิม คือสามหน้าที่ขาดสะพานคือสามหน้าที่ต้องการมันที่สุด

งานที่เพิ่มขึ้นมาจากการค้นพบนี้: คลังใช้ลิงก์สองแบบปนกันโดยไม่มีกฎ ควรถามเจ้าของว่าจะรวบให้เหลือแบบเดียวไหม แล้วเขียนลง CLAUDE.md ถ้าไม่รวบ อย่างน้อยสคริปต์ตรวจทุกตัวในอนาคตต้องนับทั้งสองแบบ

pick-books เป็นหน้าเรือธง ยาว 118,914 ตัวอักษร และ cp.ts ของมันเขียนเองว่า "ต่อยอดจากบท DP บนช่วง" แต่ในหน้าไม่มีลิงก์ไป interval-dp สักอัน ส่วน hearing-pairs คำอธิบายบอกว่า "ยกของจากบทผลรวมสะสมกับต้นไม้เฟนวิกมาใช้จริงทั้งชุด" ก็ไม่มีลิงก์เช่นกัน

สังเกตว่าสะพานเป็น ทางเดียว: segment-tree ลิงก์ออกไปห้าหน้ารวมทั้ง archery แต่ archery ไม่ลิงก์กลับ คนที่เข้ามาทางโจทย์ยากจึงเดินย้อนไปหาบทปูพื้นฐานไม่ได้

ทรงที่เสนอ

ลิงก์เดียวตรงที่เอ่ยถึง ครั้งแรก ในเนื้อความ ใช้รูปประโยคที่คลังนี้ใช้อยู่แล้ว เช่น "เครื่องมือของข้อนี้อยู่ในบทปูพื้นฐาน เซกเมนต์ทรีกับการค้นหาคำตอบแบบไบนารี" (ยืมจาก pyramid-base) หรือ "ต่อยอดจากบท DP บนช่วง" อย่าใส่ทุกครั้งที่เอ่ยถึง จะกลายเป็นรก

  • ใส่ลิงก์ 4 จุดตามตารางข้างบน หนึ่งจุดต่อการเอ่ยถึงครั้งแรกในเนื้อความ (ไม่นับที่อยู่ใน frontmatter หรือในสตริงโค้ด)
  • ตรวจว่าปลายทางทุกอันมีอยู่จริงใน dist/cp/<slug>/index.html หลังบิลด์
  • อย่าแตะลูกศรใน .dl-nav ตามกฎใน CLAUDE.md มันต้องชี้กลับไปที่ /cp/ เท่านั้น ลิงก์บทเรียนเป็นลิงก์ในเนื้อความ

เหตุผลที่ยังไม่ควรทำทันที

สารบัญจะ สปอยล์เฉลย เพราะชื่อหัวข้ออย่าง "เฉลย ตอนที่ 4 · สภาวะคงตัวมีรูปที่ตายตัวเสมอ" บอกคำตอบไปแล้วครึ่งหนึ่ง ซึ่งขัดกับหลัก reveal-after-hint ที่ทั้งคลังยึดอยู่และเป็นจุดแข็งของมัน

ทางที่พอไปได้ ยังไม่ได้ตัดสิน: แสดงเฉพาะหัวข้อก่อนสปอยเลอร์อันแรก แล้วหัวข้อที่เหลือแสดงเป็นจุดเทา ๆ นับได้ว่าเหลืออีกกี่ตอน แต่ไม่บอกชื่อ จนกว่าผู้อ่านจะกดเปิดสปอยเลอร์นั้น ต้องถามเจ้าของก่อนลงมือ

  • ถามเจ้าของว่าเอาสารบัญไหม และรับได้กับทรงไหน
  • ถ้าเอา ทำเป็นตัวเลือกของ CpProblemLayout ที่เปิดเฉพาะหน้าที่ยาวเกินเกณฑ์ ไม่ใช่เปิดยกคลัง
  • ต้องผ่านการเดินแกนกลางที่ 1500px และ 375px ไม่มี horizontal scroll ตามเช็กลิสต์ /cp/ เดิม

สิ่งที่ดีอยู่แล้ว อย่าไปรื้อ

  • ลำดับ story → spec → hint → เล่นเอง → เฉลยแบบเบลอ เป็นการจัดข้อมูลแบบ DAG จริง ให้ข้อเท็จจริงก่อนเหตุผลเสมอ
  • ทุกตัวเลขในรูปคำนวณจากโมเดลใน frontmatter หลายหน้าถึงขั้น throw ตอนบิลด์ถ้าเฉลยไม่ตรงกับ brute force
  • ทุกหน้ามีเกมให้ลองก่อนอ่านเฉลย ครบทั้ง 29 หน้า
  • โค้ดทุกชิ้นผ่าน stress-test และตัวตรวจจงใจไม่ใช้ทฤษฎีเดียวกับเฉลย
  • กล่องเล่าที่มาของแนวคิด มีอยู่แล้วทั่วคลัง ข้อ 1 คือการต่อยอดจากกล่องพวกนี้ ไม่ใช่การแทนที่

# แผนงานชั่วคราว: เติม "ที่มาของแนวคิด" ลงทุกหน้า /cp/

> **ไฟล์นี้เป็นของชั่วคราว ลบทิ้งเมื่องานเสร็จครบทุกหน้า**
> สร้างเมื่อ 2026-09-07 หลังเจ้าของอ่านชุดบทความ 16 หน้าที่เพิ่งเพิ่มเข้ามาแล้วให้ฟีดแบ็กหนึ่งข้อ

## ฟีดแบ็กที่เป็นต้นเหตุของงานนี้

เจ้าของพิมพ์มาตรงตัวว่า

> ผมอ่านคร่าว ๆ แล้วรู้สึกว่า เธอไม่ใช่ที่มาแต่ละแนวคิดเข้าไปในเฉลย เธอเล่นเฉลยเฉย ๆ แต่วิธีคิดพวกทำไมถึงคิดแบบนี้ เธอลองอะไรมาถึงมั่นใจว่าใช้แนวคิดนี้ได้ ละไปเรื่อย ๆ จนหมด เธอไม่เล่าตรงนี้เลย

แปลเป็นงาน: ทุกหน้าเปิดหัวข้อเฉลยด้วย "แนวคิดคือ..." แล้วไล่ยาวจนจบ ซึ่งเป็น**รายงานผลลัพธ์** คนอ่านได้คำตอบ แต่ไม่ได้วิธีหาคำตอบนั้น สิ่งที่ขาดคือ ทำไมถึงคิดแบบนี้ ลองอะไรมาก่อน อะไรทำให้กล้าเชื่อว่าใช้ได้ และลำดับที่ความคิดเดินไปจนจบ

เจ้าของดูตัวอย่าง 3 หน้าแล้วตอบว่า **"ทรงนี้โอเค อยากไล่ที่เหลือให้ครบเลย"** จึงไม่ต้องถามซ้ำเรื่องรูปแบบ

## ทรงที่อนุมัติแล้ว

แทรก `<div class="callout ...">` เป็น**ลูกตัวแรกใน `<Spoiler>`** ของหัวข้อเฉลยแต่ละหัวข้อ (ต้องอยู่ในสปอยเลอร์ เพราะมันคือส่วนหนึ่งของเฉลย ตามกฎ reveal-after-hint ใน CLAUDE.md)

ป้ายกำกับที่ใช้จริงแล้วในสามหน้าแรก ให้ยืมรูปประโยคไปได้เลย

| ป้าย | ชนิด | ใช้เมื่อ |
| --- | --- | --- |
| `ที่มาของแนวคิดนี้` | `callout-note` | เล่าคำถามที่ทำให้แนวคิดโผล่ ไม่มีความล้มเหลวให้เล่า |
| `สองทางที่ผมลองก่อน แล้วทิ้ง` | `callout-note` | มีทางที่ประเมินแล้วตกไปพร้อมตัวเลขที่ทำให้ตก |
| `ที่มา และสามรอบที่ยังผิด` | `callout-note` | มีการไล่หาคำตอบหลายรอบ ควรมีตารางจำนวนที่ผิดต่อรอบ |
| `เรื่องจริงที่เกิดขึ้นตามลำดับ` | `callout-warn` | บักที่ผ่านตัวอย่างในโจทย์แล้วตัวตรวจสอบจับได้ |
| `ผมแก้ถูกตั้งแต่แรก แต่เข้าใจเหตุผลผิดอยู่นาน` | `callout-warn` | แก้ถูกแต่คำอธิบายผิด และมีอะไรมาแก้คำอธิบายนั้น |

หลักการเขียนเนื้อในกล่อง

1. **เล่าเป็นลำดับเวลาจริง** ไม่ใช่ลำดับที่สวยที่สุด ถ้าตอนนั้นสังเกตก่อนแล้วค่อยพิสูจน์ ก็เขียนแบบนั้น
2. **ใส่ตัวเลขที่ทำให้ตัดสินใจ** เช่น "คูณออกมาแล้วยังหมื่นล้าน" ดีกว่า "มันช้าเกินไป"
3. **ปิดด้วยบทเรียนที่ยกไปใช้กับข้ออื่นได้** หนึ่งประโยค ไม่ต้องยาว
4. ยาวประมาณ 2 ถึง 4 ย่อหน้าต่อกล่อง ถ้ามีตารางให้ใช้ `figure.tbl` + `table.rec` แบบเดิมของหน้านั้น

## กฎเหล็กข้อเดียวของงานนี้

> **ห้ามแต่งเรื่อง** วัตถุดิบทั้งหมดที่ session ก่อนมีอยู่ ถูกจดไว้ในไฟล์นี้แล้ว
> ถ้าจะเล่าอะไรที่ไม่ได้อยู่ในไฟล์นี้ ต้อง**ลงมือทำจริงก่อน** เช่น รันโค้ดในหน้านั้นแล้ววัดเวลา สุ่มเทียบใหม่ หรือจงใจทำโค้ดพังเพื่อดูว่าตัวตรวจสอบจับได้ไหม
> หน้าไหนที่ไม่มีความล้มเหลวจริงให้เล่า ก็ให้เล่า**แรงกดดันที่บีบให้ต้องคิดท่านั้น** แทน อย่าประดิษฐ์บักที่ไม่เคยเกิด
> ดู memory `no-overclaiming` ประกอบ

## วัตถุดิบรายหน้า

โค้ดจริงกับสคริปต์สุ่มเทียบทั้งหมดอยู่ในโฟลเดอร์ scratchpad ของ session เดิม ซึ่งอาจถูกลบไปแล้ว ถ้าต้องการตัวเลขใหม่ให้ดึงโค้ดออกจากหน้าเว็บแล้วรันเอง

### 1. `anagram-window` (โจทย์ 2007)

- ไม่มีบักที่จับได้ ผ่านสุ่มเทียบ 1,200 ชุดตั้งแต่รอบแรก
- **แรงกดดัน** ไล่นับใหม่ทุกหน้าต่างคือ 3,000,000 × 3,000 = เก้าพันล้านครั้ง ในสามวินาที
- **คำถามที่ปลดล็อก** หน้าต่างสองอันที่ติดกันต่างกันกี่ช่อง คำตอบคือสองช่อง แล้วทำไมยังนับใหม่ทั้งหน้าต่าง
- **ทางกลาง** เลื่อนหน้าต่างแล้วเทียบตารางนับทั้ง 52 ช่อง คิดเป็น 1.56 × 10⁸ ครั้ง ซึ่ง**ผ่านลิมิตอยู่แล้ว** ประเด็นของตัวนับ `matched` จึงไม่ใช่เรื่องผ่านหรือไม่ผ่าน แต่เป็นท่าที่ยกไปใช้ต่อได้ ให้เขียนตรง ๆ แบบนี้ อย่าทำให้ดูเหมือนมันจำเป็น
- **กับดักที่คิดตอนออกแบบ** ถ้าเทียบ `matched` กับ 52 แทนที่จะเทียบกับจำนวนชนิดที่ปรากฏใน W โปรแกรมจะไม่เจอคำตอบเลยสักครั้ง อันนี้เป็นข้อควรระวังตอนออกแบบ ไม่ใช่บักที่เคยเกิดจริง อย่าเขียนว่าเคยพลาด

### 2. `type-printer` (โจทย์ 2008)

- ไม่มีบักที่จับได้
- **ลำดับจริง** คิดท่าไทรได้ก่อน แล้วเขียนดีพีบิตมาสก์เป็นเฉลยชุดทดสอบย่อยทีหลัง แล้วเอามาเทียบกัน
- **หลักฐาน** สุ่มคำชุดเล็ก 400 ชุด สองมุมให้จำนวนคำสั่งตรงกันทุกชุด
- **ข้อสังเกตที่เชื่อมสองมุม** `cost(a,b) = |a| + |b| − 2 × LCP` คือระยะทางบนไทรพอดี ปัญหา TSP บนต้นไม้จึงมีสูตรปิด คือ 2 × จำนวนเส้น ลบความลึกของจุดจบ
- **วิธีตรวจที่ใช้จริง** ไม่ได้เทียบแค่จำนวนคำสั่ง แต่เดินตามคำสั่งจริงแล้วเช็กว่าเซตของคำที่พิมพ์ออกมาตรงกับอินพุต 800 ชุด เพราะโปรแกรมที่นับถูกแต่พิมพ์ลำดับผิดจะรอดสายตาไปได้

### 3. `linear-garden` (โจทย์ 2011)

- ไม่มีบักที่จับได้
- **คำถามที่ปลดล็อก** เงื่อนไขพูดถึงทุกช่วงติดกัน ซึ่งดูเหมือนต้องตรวจ N² ช่วง ลองเขียนเป็นผลรวมสะสมแล้วเงื่อนไขยุบเหลือ "ค่ามากสุดลบค่าน้อยสุดไม่เกินสอง" ซึ่งตรวจได้ระหว่างเดิน
- **วิธีที่ควรสอน** เขียนเวอร์ชันที่จำทุกอย่างให้ถูกก่อน (ซึ่งกลายเป็นเฉลยชุดทดสอบย่อย 40 คะแนนพอดี) แล้วค่อยถามว่าข้อมูลชิ้นไหนไม่เคยถูกใช้จริง คำตอบคือตำแหน่งสัมบูรณ์ของผลรวมสะสม เหลือแต่ระยะสัมพัทธ์ จึงยุบเหลือหกสถานะ
- **หลักฐาน** สุ่ม 300 ชุดเทียบสองเวอร์ชัน ตรงกันหมด

### 4. `dna-kth` (โจทย์ 2016)

- ไม่มีบักที่จับได้
- **จุดยาก** นิยามรูปแบบ-j เรียกตัวเอง ต้องแกะให้กลายเป็น "นับตำแหน่งที่ตัวถัดไปเล็กลง ไม่เกิน K−1 ตำแหน่ง"
- **หลักฐานที่ใช้ก่อนเขียนโค้ด** โจทย์ยกลำดับเจ็ดตัวแรกมาให้ดู (`ACAAACAAG` ถึง `ACAAACCTG`) ผมเอาการนับรอยต่อไปตรวจกับเจ็ดตัวนั้นและกับตัวอย่างที่โจทย์บอกว่าเป็นหรือไม่เป็นรูปแบบ-3 ตรงหมด **นี่คือหลักฐานที่มีอยู่แล้วในโจทย์ ฟรี ๆ** ให้ชี้จุดนี้ว่าเป็นนิสัยที่ควรทำ
- **หลักฐานหลัง** สุ่ม 600 ชุดเทียบกับการไล่สร้างทุกตัว
- **กับดักที่คิดตอนออกแบบ** เทียบ `R ≤ cnt` ผิดข้าง กับค่าล้นที่ 4 × 10¹⁸ ทั้งสองเป็นข้อระวัง ไม่ใช่บักที่เคยเกิด

### 5. `islands` (โจทย์ 2009) มีบักจริงสองตัว

- **บักที่หนึ่ง (ในเฉลยเต็ม)** โค้ดรอบแรกคำนวณเส้นทางที่จมอยู่ในต้นไม้ห้อย (`t1[i] + t2[i]` ของทุกปม) เก็บไว้ในตัวแปร `best` แล้ว**ไม่ได้เอาไปใช้เลย** บรรทัดที่เหลือไว้คือ `(void)best;` มันคิดแต่เส้นทางที่ข้ามวง สุ่มเทียบจับได้ที่ n = 6 ตอบ 18 ในขณะที่ของจริงคือ 21 เพราะเส้นทางที่ยาวที่สุดของเคสนั้นคือ 7-1-6-2 ซึ่งอยู่ในต้นไม้ห้อยล้วน ๆ ไม่แตะวงเลย
- **ทางแก้** ต้องแจกหมายเลขกลุ่มลงต้นไม้ที่ห้อยอยู่ก่อน แล้วค่อยเอาเส้นผ่านศูนย์กลางของทุกปมมาเทียบกับคำตอบของกลุ่ม
- **บทเรียน** โค้ดที่คำนวณของถูกแล้วลืมใช้ ไม่มี error ไม่มี warning และตัวอย่างในโจทย์ผ่าน (24 ถูกต้อง) เพราะตัวอย่างของโจทย์บังเอิญไม่ได้กดดันกรณีนั้น
- **บักที่สอง (ในเฉลยชุดทดสอบย่อย)** ตอนตัดเส้นบนวงเพื่อทำให้กลุ่มกลายเป็นต้นไม้ ผมตัด "เส้นระหว่างเกาะคู่นี้" แทนที่จะตัด "สะพานหมายเลขนี้" พอเจอเกาะสองเกาะที่มีสะพานถึงกันสองเส้น (ซึ่ง**ตัวอย่างในโจทย์มีอยู่** คือเกาะ 2 กับ 7) มันตัดทิ้งทีเดียวสองเส้น กลุ่มขาดออกจากกัน ได้ 21 แทนที่จะเป็น 24
- **หลักฐาน** สุ่ม 1,500 ชุดเทียบเฉลยเต็มกับ brute และ 800 ชุดเทียบเฉลยเต็มกับเฉลยชุดทดสอบย่อย
- **ที่มาของท่าปอกใบ** ท่าที่คนคิดออกก่อนคือเดินตามลูกศรแล้วทำเครื่องหมาย แต่ต้องแยกให้ออกว่าปมที่เจอซ้ำเป็นของรอบนี้หรือรอบก่อน ปอกใบทิ้งไม่ต้องเจอปัญหานั้นเลย

### 6. `training-route` (โจทย์ 2005)

- ไม่มีบักที่จับได้ แต่มีเหตุผลชัดว่าทำไมต้องมีตัวตรวจสอบ
- **ที่มาของแนวคิด** โจทย์ใส่ขอบเขต "ทุกเมืองมีถนนต่ออยู่ไม่เกิน 10 สาย" มาให้ ซึ่งดูเหมือนของแถม ขอบเขตแปลก ๆ แบบนี้มักกำลังใบ้ว่าเฉลยต้องใช้มันตรง ๆ และมันใบ้ถึงหน้ากากบิต
- **จุดที่ไม่กล้าเชื่อตัวเอง** กฎที่ว่า "ถ้าเส้นทางไม่ทับกันเลย ก็รับประกันว่าไม่มีวงคู่โผล่มา" เป็นทิศที่พิสูจน์ยากกว่าอีกทิศเยอะ ผมจึงเขียนตัวตรวจสอบที่**ไม่ใช้กฎนั้นเลย** มันไล่ทุกวิธีเลือกว่าจะเก็บถนนเส้นไหน แล้วไล่หาวงจรอย่างง่ายทุกวงในกราฟที่ได้
- **หลักฐาน** สุ่มต้นไม้ไม่เกินเจ็ดเมืองพร้อมถนนไม่ราดยางไม่เกินห้าเส้น 500 ชุด ตรงกันหมด
- **ประโยคที่ควรมี** นี่เป็นครั้งเดียวที่กล้าพูดว่ากฎสองข้อนั้นถูก เพราะตัวตรวจสอบไม่ได้ใช้กฎนั้นเลยสักนิด

### 7. `fish-jewels` (โจทย์ 2010)

- ไม่มีบักที่จับได้
- **ลำดับจริง** ผมไล่สูตรด้วยมือบนตัวอย่างในโจทย์**ก่อนแตะคีย์บอร์ด** ได้ 1 + 2 + 4 + 4 = 11 ซึ่งตรงกับที่โจทย์ระบุว่ามี 11 ชุด และตรงกับรายการชุดทั้ง 11 ที่โจทย์ยกมา ตรงนั้นถึงกล้าเขียนโค้ด
- ตัวเลขรายบรรทัดของการไล่มือ อยู่ในตารางบนหน้าเว็บอยู่แล้ว (คอลัมน์กรณี ก และ ข)
- **จุดที่ต้องอธิบายว่าทำไมไม่ใช้เฟนวิก** มอดุลัสไม่ใช่จำนวนเฉพาะ จึงหารกลับไม่ได้ เฟนวิกตอบได้แต่ผลสะสมจากต้นถึงจุดหนึ่ง จะเอาช่วงกลางต้องหักลบ ซึ่งกับการคูณคือการหาร
- **หลักฐาน** สุ่ม 4,000 ชุดเทียบสามอย่าง คือเฉลยเต็ม เฉลยชุดทดสอบย่อย และตัวไล่นับชุดทุกชุดที่ใช้ `set` เก็บโดยไม่มีทฤษฎีกันซ้ำเลย

### 8. `pyramid-base` (โจทย์ 2013) มีบักจริงหนึ่งตัว และมีเรื่องรีดเวลา

- **บักจริง** เซกเมนต์ทรีถูกขยายให้ขนาดเป็นกำลังสอง ใบส่วนเกินถูกปล่อยไว้ที่ 0 คำตอบของ `mn[1]` จึงเป็นศูนย์ตลอดกาล โปรแกรมตอบว่าวางได้ทุกขนาด **ตอบตัวอย่างในโจทย์ถูกทั้งสองชุด** สุ่มเทียบจับได้ เคสแรกที่ปริ๊นต์ออกมาคือ M = 9, N = 6, B = 10 ซึ่งของจริงตอบ 3 แต่โค้ดตอบ 4
- **ที่มาของแนวคิดหลัก** ตารางล้านคูณล้านแตะทุกช่องไม่ได้ แต่สิ่งกีดขวางมีไม่กี่แสน ข้อมูลจริงจึงน้อยกว่าตารางมาก คำถามที่ปลดล็อกคือ**กลับด้านไปถามที่มุมล่างซ้ายของจัตุรัสที่เราวาง** แล้วก้อนหนึ่งก้อนกลายเป็นสี่เหลี่ยมบวกค่าหนึ่งผืน
- **เรื่องรีดเวลา สามรอบ** 8.1 วินาที (เกินลิมิต 5 วินาที) แล้วพบว่าตัวการคือ**การเรียงข้อมูลใหม่ทุกรอบ**ของการค้นหาแบบไบนารี ทั้งเรียงพิกัดที่บีบแล้วและเรียงเหตุการณ์ ยี่สิบรอบคือเรียงยี่สิบครั้ง แก้โดยเรียงดัชนีล่วงหน้าครั้งเดียวสี่ชุด (ตาม X1, X2, Y1, Y2) แล้วผสานสองสายที่เรียงมาแล้ว เหลือ 6.6 วินาที จากนั้นเปลี่ยนเซกเมนต์ทรีจากแบบเรียกซ้ำเป็นแบบไล่จากใบขึ้นราก เหลือ **3.8 วินาที**
- **หลักฐาน** สุ่มตารางไม่เกินเก้าคูณเก้า ก้อนไม่เกินหกก้อน 1,500 ชุด

### 9. `flood-walls` (โจทย์ 2014)

- ไม่มีบักที่จับได้ แต่มีปัญหาเชิงออกแบบที่โผล่มาระหว่างทาง
- **ลำดับจริง** เขียนเวอร์ชันตารางช่องละหนึ่งหน่วยก่อน (เฉลยชุดทดสอบย่อย 40 คะแนน) ตอบตัวอย่างถูก แล้วค่อยเห็นว่าประโยคเดียวกัน คือ "กำแพงรอดเมื่อสองข้างท่วมพร้อมกัน" ใช้ได้กับ**หน้าของกราฟระนาบ**เหมือนกัน
- **ปัญหาที่โผล่มาตอนออกแบบเวอร์ชันเต็ม** ผังอาจแตกเป็นหลายก้อน และก้อนหนึ่งอาจอยู่**ข้างในพื้นที่ปิดของอีกก้อน** ถ้าเหมารวมว่าขอบนอกของทุกก้อนคือทะเล คำตอบจะผิดสำหรับผังซ้อนผัง แก้ด้วยการยิงรังสีลงล่างจากจุดต่ำสุดของขอบนอกแต่ละก้อน แล้วรวมเข้ากับพื้นที่ที่อยู่เหนือกำแพงแนวนอนเส้นที่โดน
- **จุดที่ดูเหมือนผิดแต่ไม่ผิด** กำแพงพังทั้งเส้นพร้อมกัน ไม่ใช่พังทีละช่อง แต่การคิดราคาทีละช่องยังถูก เพราะช่องในพื้นที่ผืนเดียวกันเชื่อมถึงกันด้วยการเดินราคาศูนย์ จึงได้ค่าเท่ากันเสมอ ตรงนี้ควรเล่าว่าเคยสะดุด แล้วอะไรทำให้มั่นใจ
- **หลักฐาน** สุ่มผังบนแลตทิซ 3,000 ชุด (ใช้เส้นยาวหนึ่งหน่วยซึ่งไม่มีทางตัดกันเอง และสร้างผังซ้อนผังได้ตามธรรมชาติ) เทียบเวอร์ชันหน้ากับเวอร์ชันตาราง ตรงกันหมด

### 10 ถึง 14. บทปูพื้นฐานทั้งห้า

บทปูพื้นฐานไม่มี "เรื่องเล่าการไล่หาเฉลย" แบบโจทย์ ให้ใช้ทรงที่ต่างออกไปเล็กน้อย คือกล่อง `ที่มาของท่านี้` ที่ตอบว่า **อะไรพังถ้าไม่ใช้ท่านี้** และ **อะไรทำให้รู้ว่าท่านี้ใช้ได้กับโจทย์ตรงหน้า**

- **`sliding-window`** จุดขายคือคำถามตัดสินว่า "ถ้าขอบขวาขยับ ขอบซ้ายมีทางถอยกลับได้ไหม" ให้เล่าว่าคำถามนี้คือสิ่งเดียวที่ต้องถาม และเคสที่ตอบว่าได้ (อาเรย์มีเลขติดลบ) ท่านี้ผิดทันทีแบบเงียบ ๆ ส่วนกับดัก `while` กับ `if` ในโจทย์ฝึกข้อสอง ตอบตัวอย่างง่าย ๆ ถูกได้สบาย
- **`trie`** ให้เล่าว่าก่อนเลือกไทรต้อง**คูณเลขหน่วยความจำออกมาก่อน** คำแสนคำ คำละยี่สิบตัว ไม่มีส่วนหัวซ้ำเลย คือสองล้านปม คูณ 26 คูณ 4 ไบต์ ได้ราว 208 เมกะไบต์ ซึ่งเกินลิมิตของโจทย์ส่วนใหญ่ นี่คือขั้นที่คนข้ามแล้วตกทีหลัง
- **`count-then-walk`** สองบักที่เกิดกับทุกคนคือเทียบผิดข้าง (`R < cnt` แทน `R ≤ cnt`) ซึ่งเลื่อนคำตอบไปหนึ่งช่องเสมอ กับค่าล้น ให้เล่าว่าทำไมสองอันนี้ถึงจับยาก คือมันยังดูสมเหตุสมผลและยังตอบเคสเล็กถูก
- **`functional-graph`** **มีบักจริงให้เล่า** โค้ดข้อฝึกที่หนึ่ง (เดิน k ก้าว) ผมคำนวณระยะจากปมบนวงลงมาถึงตัวเอง**ก่อน**ผลักตัวเองเข้าสแต็ก พอ k เป็นศูนย์มันจึงอ่านเลยขอบอาเรย์ สุ่มเทียบ 3,000 ชุดจับได้ทันทีที่ k = 0 โผล่มาชุดแรก ผลที่ได้คือ `1 363 3` แทนที่จะเป็น `1 2 3` และให้เล่าด้วยว่าทำไมถึงเลือกปอกใบทิ้งแทนการเดินตามลูกศร
- **`segment-tree`** ให้อ้างบักใบส่วนเกินของ `pyramid-base` ตรง ๆ ว่านี่คือกับดักที่ผู้เขียนตกมาแล้วจริง และให้เล่าว่าเงื่อนไขเดียวที่การค้นหาคำตอบแบบไบนารีต้องการคือความไม่ลด ซึ่ง**ต้องตรวจจริง ไม่ใช่เดา** โดยอ้าง `archery` ที่คำตอบเรียงเป็น 4 2 2 4 ทำให้ท่านั้นใช้ไม่ได้

## ขั้นตอนทำงานที่แนะนำ

1. ทำทีละหน้า แก้ไฟล์ `.astro` ตรง ๆ ด้วย Edit ได้เลย ไม่ต้องใช้สคริปต์ patch (สามหน้าแรกใช้สคริปต์เพราะแก้ทีเดียวหลายจุด)
2. **ระวังท้ายบรรทัด** `archery.astro` เป็น CRLF ส่วนอีก 15 หน้าเป็น LF อย่าเผลอเปลี่ยนทั้งไฟล์
3. หลังแก้ทุก 3 ถึง 4 หน้า ให้รัน `npm run check` แล้ว `npm run lint`
4. ก่อนถือว่าเสร็จทั้งชุด รัน `npm run build` และเช็ก
   - `grep -c '—'` ต้องเป็น 0 ทุกไฟล์ใน `src/pages/cp/`
   - ไม่มี zero-width space
   - เปิดเบราว์เซอร์แล้ววัดว่าไม่มีบล็อกไหนเอียงออกจากแกนกลาง (วิธีวัดอยู่ใน CLAUDE.md หัวข้อ "A new block class is invisible to the centring rules")
   - ที่ 375px หน้าไม่เลื่อนแนวนอน
5. commit เมื่อเจ้าของสั่งเท่านั้น เจ้าของสั่ง commit ชุดนี้ไปแล้วรอบหนึ่ง แต่งานเติมเรื่องเล่ายังไม่ได้สั่ง
